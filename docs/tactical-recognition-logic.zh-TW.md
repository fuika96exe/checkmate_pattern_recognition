本文按目前程式實際執行的條件，解釋中國象棋戰術標籤怎樣產生，並指出規則的適用範圍。這些標籤是程式根據局面和短期變化作出的描述，不等同引擎證明該着是最佳着，也不保證符合所有棋書對名稱的定義。

## 中局題瀏覽器 v3.0 的獨立契約

正常中局題入口 `CapturingTacticsLab` 讀取 `public/data/capturing-tactics.json`；批次入口 `label_puzzle` 經 `analyze_midgame_categories(fen, blunder, pv, solver)` 呼叫 [midgame_tactics.py](../backend/app/midgame_tactics.py)。CSV 匯入先套用既有 `adapt_upload_row`；重新分析舊資料亦走同一入口，完全重算，沒有把 big/small 映射為新分類。

完整時間線是 B0（失着前）、B1（失着後）、原題 PV 的各局面。ply 1 是失着，ply 2 是玩家首着。只重播一次，所有步驟都用真實行棋方驗證；雙方着法都更新各自獨立的持久棋子 ID 快照。失着參與計分、但不發標籤。假設輪到玩家的 `view` 只替換 FEN 行棋方並保留其餘欄位，不會當作 PV 停着。缺王、錯誤 FEN、空 PV、行棋方錯配或非法着均回報 `invalid`，附 `id/sourceRow/errorPly/errorFen/errorMove`，不歸入「並非得子」。

每道有效題必有唯一分類。D(B) 是玩家的車馬炮總值減對方車馬炮總值，車 9、馬炮 4；`material.start/end/delta` 分別是 D(B0)、D(終點) 及兩者差。`delta >= 4` 為 `gain`（得子），其餘 `no_gain`（並非得子）。士象兵及 score 不影響整題分類。這與局部交換估值分開。

有利吃子使用本 repo 的 `evaluate_exchange`，要求實際佔據目標格、合法且淨收益嚴格大於 0。王只驗證真實將軍來源，不送入交換估值。普通車馬炮目標沒有非殘局 >1 的威脅門檻。通用 `profitable_capture` 適配層另保留上游非殘局時非兵吃未過河兵的例外；回傳的 signed gain 用於覆核，非法／不適用回傳 `None`，不以 0 證明等價交換。上游參照固定為 [fake_humans.py](https://github.com/DamianKan/Xiangqi-app/blob/09f4fd2dc755fe8dec7366778eef107be3f9c577/xiangqi-server-master/xiangqi_server/api/util/fake_humans.py) 與 [exchange.py](https://github.com/DamianKan/Xiangqi-app/blob/09f4fd2dc755fe8dec7366778eef107be3f9c577/xiangqi-server-master/xiangqi_server/api/util/exchange.py)；本機批次不連線，座標始終用 repo UCCI 0–9。

### 有效威脅原則（人工專家確認，2026-11-04）

**只有「吃過去的交換價值 > 0」的攻擊才算有效威脅。** 這是人工審查中局題時一致採用的判準，適用於所有以「威脅」構成的標籤：

- 捉雙的每個目標、閃擊新增的攻擊、串打前後段、牽制後方大子、圍困的原捉子、消除保護及消除阻隔兌現前的攻擊、抽將中非將軍的那個目標，都必須是交換價值 > 0 的有利吃子；王只以真實將軍計。
- 交換價值 = 0 的攻擊不是威脅，包括：
  - 同值邀兌，例如車對車而對方可回吃；
  - 攻擊有保護的子，吃過去後被回吃且淨值 ≤ 0。
- 交換標籤中，對手的吃子若交換價值 ≤ 0（例如炮吃有保護的馬後被回吃），不應被當作構成交換的有效吃子。

目前 v2.5 實作仍有偏離這條原則的已知個案，例如把邀兌算成閃擊或捉雙，以及把無效吃子算成交換。這些個案由專家修正後記錄在 [已知錯誤清單](../backend/tests/fixtures/midgame_frozen/known_wrong_v1.json)，作為日後修正規則的依據。修正時須按本文件流程升規則版本，並通過凍結回歸集。

中局題只輸出以下十個 ID；每題 `tactics` 去重，逐手 `occurrences` 保留最終標籤證據，`supportingEvidence` 保存被去重的有效支援證據，summary 只按最終標籤逐題計數。

| ID | 實際規則與保守取捨 |
| --- | --- |
| `fork` 捉雙 | 同一棋子走後對兩個不同目標有有利吃子或真實將軍，至少一個威脅為新增。炮將軍的己方炮架若新增攻擊另一大子亦算。對手若可合法先吃攻擊子且同格交換收益 ≥ 0，則不標捉雙；其他應手不排除。 |
| `discovered_attack` 閃擊 | 移動 A 的出發格是另一己子 H 新增合法攻擊敵車馬炮王的必要阻擋格。用佔位副本恢復出發格核對；解除馬腿、象眼、車線、多餘炮架均可。新增炮架及只吃掉落點阻擋子不算。 |
| `skewer` 串打 | 新車炮射線，前後均為敵車馬炮王，前值 ≥ 後值，王 99999。前段與前子合法離線後的後段均須交換收益 >0；前子是王則以真實將軍取代估值。保存合法分支並優先記錄保持原線、原炮架的實際 PV；攻擊子下一手被吃則不引用其未兌現串打。不可建立缺王 FEN。 |
| `pin` 牽制 | 車炮射線、馬腿或象眼的對方前子移除後，後方大子須可被合法有利吃取；車炮直線另要求後子價值高於前子。前子能合法且不虧地立即吃掉牽制者時不標牽制。絕對及相對牽制均須有棋譜實際有利得子證據。 |
| `check_fork` 抽將 | 本手實際將軍，而且同手有效 fork／discovered_attack 目標或 skewer 前子含敵王；保存父 occurrence key 與實際將軍來源。不繼承尚未解除的將軍來抬高另一吃着的收益。 |
| `trap` 圍困 | 車馬炮原格已有有利吃子；逐一檢查合法逃着。若逃後新增對另一己子的有利吃子且扣除補償後的淨損失嚴格大於原目標面臨的損失，也是否定逃路的證據。同一棋子已有有效牽制標籤時不標圍困。 |
| `remove_defender` 消除保護 | 同一攻擊者對同一車馬炮從無利變有利，失去原可合法回吃的守子，後續玩家實際有利吃取。支援直接吃守子、攔截其保護線，以及受玩家威脅／將軍而在 PV 實際離開的守子；取消唯一合法應着門檻。守護或不利狀態恢復即中止。尚無先前合法攻擊者的早期準備送覆核。 |
| `overload` 過載 | 同一守子原可合法回吃兩個大子的假設吃着；玩家實吃其一，守子實際回吃導致另一目標由無利變有利，玩家後續兌現。取消唯一合法應着門檻，先實驗實際 PV 因果鏈，不聲稱已搜索所有替代應法。單純兼守、未兌現或守護恢復不標。 |
| `exchange` 交換 | PV（不含失着）中玩家與對手均吃掉大子。同一落點可任意隔步；異格要求原始 ply 相鄰。不限制吃子者、等價性或收益，掛在玩家吃子手，確認手取較後者。 |
| `clearance` 消除阻隔 | 玩家新建立有利威脅或將軍，PV 中敵方阻隔子實際離開必要阻擋格，令另一己子原本不存在的合法攻擊變得有利，並由同一攻擊子實際有利吃同一大子。保存施壓、阻隔子身份、騰空格、開線、兌現。阻隔恢復或線路中斷作廢；同一攻擊者本可攻前子、其離線露後子的情形保留為串打，不重複算 clearance。 |

v2.5 的共用判斷及去重順序（v2.6 的增補見文末）：

1. 除捉雙外，玩家本手交換估值 **≤0**，且原始時間線下一個半回合實際吃掉同一移動棋子 ID，則排除它提供的未兌現威脅。捉雙以對手立即吃掉攻擊子的交換淨值另行判斷。
2. 捉雙在走後局面查詢同一棋子的將軍及有利吃子；對手應將只用來檢查其能否合法且不虧地立即吃掉攻擊子。其他戰術對受將局面的查詢仍按各自的確認規則處理。
3. 圍困的間接損失須為逃着後新增，且扣除補償後嚴格大於原先對被捉棋子的損失；等額不算。
4. 牽制一直追蹤到每個真實局面；新形成、應着確認、利用既有關係分開記錄。反事實解除牽制只作證據查詢，保留雙王，不會寫入真實 PV。
5. 僅對 `gain` 題：有其他有效標籤時抑制 exchange；捉雙與抽將可同時顯示。被去重的有效項目放入 `supportingEvidence`。

`matched/unmatched` 只代表有無標籤。證據保留 `triggerPly/confirmedPly/actors/targets/relationKind`、身份與格位、候選 UCCI／gain、炮架、合法支援分支、逃着或實際兌現着。瀏覽器可跳至觸發／確認局面，展開完整機讀證據與 `reviewReasons`。無法可靠證明因果的候選不發標籤；覆核原因與解析／重播 invalid 分開計數。

## 共用辨認流程

```text
起始 FEN ＋ UCCI 走法
          ↓
逐手重播，取得每手走前、走後的棋盤
          ↓
產生合法着法及攻擊圖，並比較走前、走後的關係
          ↓
分別執行「戰術分類」及「走子目的」規則
          ↓
每手輸出命中標籤、相關棋格和文字說明
          ↓
棋局工作台再按識別碼合併結果
```

- FEN 包含棋子位置和行棋方；走法使用 UCCI，例如 `b2e2` 表示由 `b2` 走到 `e2`。棋盤以紅方視角計，`a–i` 由左至右，`0–9` 由紅方底線至黑方底線。
- 每手結果包含 `ply`、`side`、`ucci` 和 `occurrences`；每個命中項包含識別碼 `id`、中文名稱 `label_zh`、相關格子 `squares` 及說明 `detail`。一手可以同時命中多個標籤，也可以沒有標籤。
- 合法着法由 [board.py](../backend/app/board.py) 提供，會考慮炮架、蹩馬腿、將帥安全等規則；攻擊圖描述棋子的幾何攻擊。兩者用途不同：「有攻擊」不一定代表該着合法，或吃下後一定得子。
- 重播過程依賴提供的棋譜。起始 FEN 不包含之前的走子歷史；例如某次較早的吃子，若不在輸入棋譜內，就不能用來辨認後來的實際反吃。
- 戰術分類和走子目的各有自己的規則，即使中文名稱相似，也不保證判定相同。它們與將死殺法分類、重複局面的長將／長捉裁決是不同功能。

## 子力交換計算

走子目的的「交換」、「吃」、「捉」，以及部分「棄」判斷，使用 `evaluate_exchange` 計算**同一落點**的連續吃子與回吃：

1. 固定候選着法，然後枚舉對方在該落點的合法回吃。
2. 每次回吃後重建局面，再枚舉另一方的合法回吃；雙方各自選擇對自己最有利的結果。
3. 通常可以停止不利的回吃；如果正在被將軍，而且所有合法應着都只能回吃該落點，就必須繼續。
4. 每次回吃都減少一枚棋子，因此遞迴自然終止。結果是該候選着對行棋方的子力淨收益。

子值為車 9、馬／炮 4、士／象 2、未過河兵／卒 1、過河兵／卒 2。參與交換的棋子按每次移動前的位置計值，例如吃子過河的兵按出發格計值。

這不是全局搜索：它不計算其他格子的後續變化、攻勢或將殺補償。其他分類也可能只檢查一次合法回吃或幾何保護，不能把它們一律理解為使用了完整交換計算。

## 戰術分類

程式版本名稱保留 `nine-tactics`，但目前 `LABELS` 實際列出以下**八個**識別碼。分類主要比較本手走前、走後的關係；並非每項都要求實際吃子。

### 1. 交換 `exchange`

- 本手實際吃掉的棋子，必須是之前某次吃子後留在原落點的吃子者。
- 反吃發生在原吃子之後最多三個半回合（ply）內；中途有其他着法或吃子，也不一定抹掉這段關係。
- 原來吃子者和被其吃掉的棋子，以原位置計算的子值必須相等。
- 馬／炮吃士／象、再被另一隻士／象回吃，而且己方仍可回吃的特定棄子結構，被排除在此分類之外。

此分類要看到實際反吃，並以原先兩子的價值作近似判斷；它並不等同走子目的中，依整條落點交換計算淨收益為零的「交換」。

### 2. 捉雙 `fork`

程式比較走前、走後的合法吃子，尋找本手**新增**的有效攻擊：

- 新增至少兩個不同的敵方車、馬、炮目標；或者本手形成將軍，同時新增對至少一個敵方車、馬、炮的攻擊。
- 攻擊可以由同一棋子發出，也可以是本手移子後，另一枚己子開線形成；走前已有的無關攻擊不能直接湊數。
- 同類車、馬或炮若可以合法反過來吃攻擊者，該關係會被排除。一般目標還要沒有幾何保護；馬或炮攻車則有例外，即使車受保護也可計入。

兵、士、象不作為這裏的第二個子力目標。規則沒有逐一證明對手無法同時化解全部威脅；輸出文字提及「安全」時，仍應按上述實際過濾條件理解。

### 3. 串打 `skewer`

目前只認**炮**的新增線路關係：炮合法攻擊前方敵子；假設移走前子後，炮可合法攻擊同線後方敵子。前子現時無幾何保護，後子在前子移走後也無幾何保護。

未過河兵卒不作為前後目標；同類子可以合法反吃攻擊者等情況亦會過濾。程式保留炮原有的炮架，只檢查最近符合條件的後方目標。車的同線攻擊不會由這條規則標為串打。

### 4. 閃擊 `discovered_attack`

程式只接受以下明確分支，並按順序最多輸出其中一種：

1. 移開馬腿，令己方馬新增合法吃子。
2. 移動非車棋子，令己方車新增將軍。
3. 移動非車棋子，令己方車新增攻擊無幾何保護的敵車、馬或炮，且該車本身不能被對方直接合法吃掉。
4. 移動非炮棋子，令己方炮新增將軍，而移動到落點的棋子同時新增攻擊無幾何保護的敵車、馬、炮，或過河兵卒。

所以，並非所有開線攻擊都會標為閃擊；例如單純讓炮開線攻子，但不符合上述配合將軍分支，可能不命中。

### 5. 消除保護 `remove_defender`

- 本手必須**直接吃掉**一枚敵方車、馬或炮；被保護目標亦限敵方車、馬或炮，而且仍在棋盤上。
- 走前該守子對目標有程式認可的合法回吃保護；走後目標失去所有計入的保護，並可被己方合法直接攻擊。
- 保護關係會排除某些原本已可用低價棋子獲利吃取的目標。若新增吃法全部只是同類棋子之間可合法互吃，也會排除。

單靠牽制守子、改變路線或吃掉被保護目標本身，不會觸發這個標籤。士、象、兵等雖可在其他規則中提供保護，在這條規則中不算合資格守子。

### 6. 圍困 `trap`

程式先找走後正被己方合法直接捉住的敵子，再檢查該子每一條可列出的合法走法：若每個落點都可被對方立即吃取並構成規則所接受的失子威脅，就視為被困。

目標剛被困，或它原已被困但本手新增了直接捉它的棋子，均可命中。馬／炮攻受保護的車有子力差例外。將帥及未過河兵卒不作目標；程式也不把被將軍時全盤必須應將造成的暫時限制，當作單子被圍困。

此檢查限於局部、即時的逃走與吃子；沒有走法的棋子不一定會被此實作列入候選，亦沒有證明所有其他救子手段均無效。

### 7. 牽制 `pin`

程式報告本手新增的多種約束關係，包括：

- **絕對牽制**：某子離開車或炮與己方將帥之間的相關線路，會暴露將軍，因此該離線着不合法。分類規則在此分支只接受被牽的車、馬或炮；炮線還須有另一個炮架。
- **同線子力牽制**：車、炮與敵子形成符合規則的線路，移開前子會暴露後子；部分分支要求相關子力為車、馬、炮，並檢查保護及互吃情況。

程式另有「前子有保護」的線路牽制分支，並以走前關係去重。雖然程式保留回吃保護牽制的輔助函式，目前主要呼叫路徑不會輸出該分支。這是特定棋子及線路上的判斷，不是對所有戰略牽制的完整證明。

### 8. 炮兵突破 `cannon_pawn_breakthrough`

常見分支嘗試以下短變化：

1. 未過河兵卒合法前進；這手可以已經走出，亦可以在炮先就位後由程式假設下一手走出。
2. 對方有兵卒可以合法吃該兵，並且沒有其他種類的敵子可以合法吃該兵。
3. 對方按候選應着吃兵後，己方炮可以合法吃到無法立即合法回吃的棋子；若目標是車，即使有回吃也接受炮換車的子力差。

程式找到一條符合條件的候選回應及炮吃變化便可命中；不代表對方必須吃兵，也不代表所有應着都會失子。

另有將軍分支：挺兵後對方兵卒在幾何上可吃該兵，但實際沒有合法吃兵着；假設該卒吃兵會暴露炮對敵將的攻擊，也可標為炮兵突破。

## 走子目的

走子目的同樣逐手輸出，可用來描述本手造成的直接效果。以下是現行主要條件，並非對棋手意圖的心理判斷。

| 標籤及識別碼 | 程式主要判斷 |
| --- | --- |
| 交換 `exchange` | 本手實際吃子，同一落點的完整交換淨收益為 0。 |
| 吃 `capture` | 本手實際吃子，完整交換淨收益大於 0；非殘局時，非兵卒吃未過河兵卒不標「吃」。 |
| 捉 `chase` | 本手新增合法且有利的吃子威脅。非殘局要求淨收益大於 1，並排除未過河兵卒；殘局要求大於 0。移開其他棋子開線也可命中；同一攻擊者換位後繼續捉同一目標不重複標記。 |
| 逃 `escape` | 被直接攻擊的移動棋子，走後的即時交換預期損失降低；直接吃掉攻擊者不算這裏的「逃」。 |
| 保 `protect` | 原本受有利吃子威脅的己子，本手首次獲得可合法回吃的保護；可以是移動的棋子保護，也可以是讓開線路使另一己子保護。應將時不輸出此項。 |
| 棄 `sacrifice` | 本手移子造成符合條件的子力淨虧，或留下／新增另一己子可被安全吃取的具體威脅；亦有應將棄子、過河兵受攻及馬炮換雙士象等特例。這不證明棄子是有意或有補償的。 |
| 擋 `block` | 棋子進入敵車路線，使車可到達的路線縮短；若擋子可被安全吃掉，或正在應將，相關分支不標「擋」。 |
| 封鎖 `seal` | 已阻擋敵方車或炮線路的棋子，沿同一線靠近該車／炮，使其活動範圍進一步縮小。 |
| 困 `trap` | 本手新增對敵子的受困關係，按走子目的自身的局部逃走、受攻及保護規則判斷；條件不完全等同戰術分類的「圍困」。 |
| 牽 `pin` | 本手新增同線或絕對牽制關係；與分類的「牽制」使用獨立的規則實作。程式保留回吃保護牽制的輔助函式，但目前主要呼叫路徑不會輸出該分支。 |

「殘局」在這裏是程式門檻：雙方各自的車馬炮總數都不超過兩枚，**或**雙方都沒有車；不是對棋局階段的全面評估。更詳細的交換、吃、捉規則見 [手法識別文件](move-purpose-rules.md)。

## API 與工作台怎樣顯示

- `POST /api/analyze-tactics` 接收 `fen` 和 `ucci_moves`，回傳走子目的版本及逐手標註。
- `POST /api/analyze-tactical-categories` 接收相同形式的輸入，回傳戰術分類版本及逐手標註。兩個實驗室可各自查看原始結果。
- 棋局工作台報告會以完整提供的棋譜執行兩套分析，再取指定手的結果；同時加入將軍、將死、困斃及重複局面等規則事件。
- 合併時先保留走子目的；若戰術分類出現相同 `id`，便略過該分類項。若走子目的已判為獲利「吃」，亦略過分類中的「交換」。這是按識別碼去重，不是逐一核對兩項的格子或因果關係。

## 使用結果時要留意

- 這些規則有明確的棋子種類、位置、歷史和短期變化限制。沒命中不代表局面沒有相應戰術；命中也不代表該戰術一定決定勝負。
- 幾何保護、合法回吃、單次安全吃子及完整落點交換是不同層次的判斷；各標籤使用的層次並不相同。
- 假設變化只證明程式找到指定變化，除非規則明確逐一檢查，否則不能推論對方所有應着都失敗。
- 標籤名稱相同或相近時，應查看它來自哪套規則及其 `squares`、`detail`；工作台合併後的顯示可能比兩個實驗室的原始結果少。

## 得子棋題 v2.6 補充（2026-11-04，依人工審查 219 題修訂）

以下改動都由專家審查結果推出，並以凍結回歸集 v1 驗收。原表格描述的 v2.5 行為，除下列各點外不變。

- **交換**：失着本身吃掉大子，而玩家下一手（ply 2）立即吃回**等值**大子（車對車、馬炮互換），也算交換，`relationKind` 為 `blunder_trade_recaptured`。吃回較大的子屬於得子，不算交換。得子題有其他標籤時仍照舊抑制交換。
- **圍困**：以下兩種情況不標圍困，並記入 `reviewReasons`：
  - 目標在走前或走後是任何牽制關係的前子（`target_is_pinned_front`）。這時它走不了是因為被牽制，應歸入牽制。
  - 目標已是同一手串打的目標（`target_explained_by_line_tactic`）。v2.6 原本也包括閃擊目標，v2.7 依裁決 D2 取消。
- **牽制**：新增兩種「借牽制得子」證明。
  - `pinned_front_won`：牽制關係形成或被利用之後，前子一直沒有離開原格，最後被玩家有利吃掉。即使對方先墊子或加保護，令關係在吃子前已經消失，仍然成立。
  - `illegal_recapture`：玩家有利吃子，對方本來可以回吃的子，因為回吃會令自己的將帥受將（包括將帥對面）而不能回吃。另外，吃子者的價值不低於被吃子，即沒有牽制時，這次吃子並不有利。這種證明以 `illegal_recapture` 關係記錄。
- **捉雙**：一手同時將軍和攻擊另一子時，非將帥的那個目標必須是本手新增的攻擊。將軍加上原本已存在的攻擊，不算捉雙（`check_with_preexisting_attack`）。
- **串打**：玩家必須在 PV 中實際吃到線上前子或後子（大子）。可以墊將化解，或後子有保護而沒有兌現的串打，不再標記（`skewer_not_realized`）。由串打推導的抽將亦隨之取消。

## 得子棋題 v2.7 補充（2026-11-04，依專家裁決 D1–D4）

- **閃擊（D1）**：開出的攻擊必須是真實將軍，或交換值 > 0 的有利吃子。交換值 = 0 的開線攻擊（例如車對車邀兌）只有在同一手將軍時才算，因為對方要先應將，無法處理被開出的攻擊（`revealed_attack_not_profitable`）。
- **閃擊（D2）**：不要求「一步攻擊兩點」。被開出的子單獨構成有效攻擊即可。
- **抽將（D3）**：除原有條件外，還須滿足以下其中一項，否則不標（`no_profitable_capture_after_check`）：
  - 對方實際應將後，玩家有交換值 > 0 吃車馬炮的選項；
  - 父戰術是閃擊，而且走動（閃出）的子本手吃掉車馬炮。
- **牽制（D4）**：本手由走動子新造成的牽制，若被牽制子受有利攻擊且所有逃着都失子，標牽制（`pinned_target_cannot_escape`），不標圍困。
