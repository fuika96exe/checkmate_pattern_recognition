# 手法识别：交换、吃、捉

规则版本：`tactics-draft-0.2`。这三个标签加入「手法识别」，并随走子目的汇总到棋局工作台。

参考 `xiangqi-server-master/xiangqi_server/api/util/fake_humans.py` 中的
`is_trade`、`is_capturing_move`、`_process_threat_candidate` 和 `is_endgame`，
以及同目录 `exchange.py` 的静态交换计算。参考项目的 1–10 路径坐标在此转换为
本项目的 0–9 UCCI 坐标；FEN 的红方大写、黑方小写约定保持不变。

## 同一落点的交换计算

固定候选着法后，枚举双方在该落点上的所有合法回吃，逐层选择对自己最有利的结果。
每次吃子都重新计算合法着法，因此炮架、马腿、象眼、牵制和将帅照面会随局面更新。
可以停止不利的回吃；如果正在被将军，且所有合法应手都只能回吃该落点，则必须继续。
每次回吃都会减少一枚棋子，计算自然终止，不截断为固定搜索层数。

子值为车 9、马炮 4、士象 2、未过河兵卒 1、过河兵卒 2。
参与交换的棋子按该次移动前的格子计值，避免兵卒在吃子过河后被多算一分。
只计算这个落点的子力得失，不评价其他位置的攻势、将杀补偿或整盘最佳着法。

## 标签条件

- **交换**：实际合法吃子，并且完整交换的净收益为 0。未实际吃子的兑子邀请不属于此标签。
- **吃**：实际合法吃子，并且完整交换的净收益大于 0。非残局时，非兵卒棋子吃未过河兵卒不标记；兵卒吃兵卒保留例外。残局允许计入未过河兵卒。
- **捉**：本手新增可获利的合法吃子威胁。非残局要求净收益大于 1，并排除未过河兵卒目标；残局要求净收益大于 0，并允许未过河兵卒目标。移动其他棋子打开攻击线也可以形成捉。

残局定义与参考项目一致：双方各自的车马炮总数都不超过两枚，或者双方都没有车。

「捉」比较走前和走后的攻击者／目标关系，跟踪本手移动棋子的身份。
同一棋子换个格子继续攻击同一目标，不重复标记；断开后重新建立的威胁可以再次标记。
每项结果输出相关格子与交换净收益，供人工核查。

这些规则独立于重复局面的长捉裁决，也独立于「战术分类」的规则。
工作台合并结果时，已判定为「吃」的获利吃子不会再显示战术分类中的近似「交换」。
实际吃子后的普通「弃」采用相同的完整交换净亏，避免等价交换或获利吃子仅因能被回吃而同时误报弃子。
原有的马炮换双士／双象这一战略弃子特例保留，因此它仍可与物质上等价的交换同时出现。
其他逃、保、挡、封锁、困、牵，以及不涉及实际吃子的弃子，继续按原有规则计算。

仅转换着法坐标，预期净收益保持不变。相同案例同时验证 Pyffish 和纯 Python 棋规。
另有标签、残局阈值、兵卒例外、持续捉子去重、API 序列化和工作台汇总测试。
